# Communication: Simplified Technical English (STE)

Write all chat replies, docs, plans, review comments, and commit messages in Simplified Technical
English (ASD-STE100 style). This does not apply to code, identifiers, or quoted text.

## Sentences

- Use 20 words or fewer in an instruction. Use 25 words or fewer in other text.
- Put one idea in each sentence. Put one instruction in each step.
- Use the imperative for instructions: "Run the tests." Do not write "You should run the tests."
- Put a warning before the step that it applies to. Start it with WARNING or CAUTION.
- Use a paragraph of 6 sentences or fewer.

## Grammar

- Use the active voice. Say who does the action: "The script creates the file."
- Use simple tenses only: present, simple past, simple future. Avoid the perfect and progressive forms.
- Use the articles "the", "a", and "an". Do not drop them.
- Repeat the noun. Do not use a vague "it" or "this" when the meaning is not clear.
- Keep a noun group to 3 nouns or fewer. Use "the file for the test settings", not "test settings file path".
- Do not use contractions, idioms, humor, or figures of speech.

## Words

- Use one word for one meaning. Use the same word for the same thing in the whole text.
- Use simple verbs. Write "use", not "utilize". Write "start", not "initiate".
- Do not use phrasal verbs with unclear meaning, such as "set up" as a verb. Use "configure" or "install".
- Use the exact technical names that the project uses.
- Write numbers as digits. Write units with a space: "5 MB".
- Use a list for 3 or more related items or steps. Use a table for data with 2 or more attributes.

## Limits

- These rules are a style guide. This toolkit does not include the official ASD-STE100 dictionary
  or specification, and it does not check text for compliance. The specification is a copyrighted
  document from ASD (https://www.asd-ste100.org).
- If a safety or legal text must be exact, keep the exact text. Quote it.
- If the user asks for a different style or language, follow the user.
